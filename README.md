# VPf09 - AI-бот ВКонтакте

Базовый вариант домашнего задания: VKBottle LongPoll, модель `openai/gpt-6-luna`
через ProxyAPI, пять ролей общения и независимые диалоги с JSON-памятью.

## Возможности

- Главное меню: новый диалог, список диалогов, смена режима, настройки, помощь.
- Роли: обычный помощник, программист, преподаватель, бизнес-консультант,
  дружелюбный собеседник. При смене роли контекст текущего диалога сохраняется.
- Переключение, переименование и удаление диалогов; очистка текущей истории.
- Отдельный `users/<vk_user_id>.json` на пользователя. В каждом диалоге сохраняются
  последние 100 реплик с ролями и временем; данные доступны после перезапуска.
- В настройках видны модель и фактические счётчики токенов из ответов ProxyAPI.

## Запуск

Python 3.10+ на macOS/Linux. Настройте сообщество VK: сообщения сообщества,
возможности ботов, LongPoll API и событие входящего сообщения.

```bash
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
cp .env.example .env
```

В `.env` задайте токен **сообщества** `VK_BOT_TOKEN` и ключ `PROXYAPI_KEY`.
Базовый адрес - `https://api.proxyapi.ru/v1`. Модель можно изменить через `MODEL`.
Не запускайте два разных LongPoll-бота с одним токеном одновременно.

```bash
.venv/bin/python bot.py
```

Напишите боту `Начать`. В настройках текущего диалога доступны переименование,
очистка истории и удаление. Команда `Меню` отменяет ввод названия.

## Проверка

```bash
.venv/bin/python -m unittest -v test_bot
.venv/bin/python check_live.py
```

Вторая команда делает **6 платных запросов** к ProxyAPI и сохраняет локальный
протокол в соседней папке `VPf09 - ДЗ.assets`. Проверяет API и логику памяти,
а работу VK-интерфейса нужно проверить отдельно перепиской с ботом.

27 октября 2026: 20 автономных тестов и 6 реальных API-проверок прошли успешно.
В API-проверках использовано 1285 токенов (764 входных, 521 выходной).

При ошибке VK `29 - Rate limit reached` бот пишет в журнал, что LongPoll
недоступен, и ждёт 300 секунд до следующей попытки. При обычной сетевой ошибке -
30 секунд. Запись о старте процесса сама по себе не подтверждает приём сообщений:
в журнале должна появиться строка «LongPoll отвечает корректно».
Если сервер отклоняет полученную сессию (`failed: 2`), обновление также выполняется
с паузой 300 секунд, чтобы не исчерпать лимит запросами по кругу.
